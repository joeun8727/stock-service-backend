# 04 — 섹터 유망도 랭킹

## 목표

현재 미장에서 유망한 섹터를 **1~5위**로 랭킹.

## 데이터 소스

- **Finnhub**: 섹터별 종목 재무지표 (PER, 성장률)
- **FRED**: 거시지표 (기준금리, GDP 성장률, 산업생산지수 등)
- **NewsArticle 테이블**: 섹터별 뉴스 볼륨 & 평균 감정 점수 (이미 수집된 데이터 활용)

## 대상 섹터 (Phase 1 고정 리스트)

초기에는 주요 섹터를 코드에 정의 (추후 동적 확장):
반도체, 우주/항공, AI/소프트웨어, 전기차/배터리, 헬스케어/바이오,
에너지, 금융, 소비재 — 등 8~10개로 시작.

## 점수 산출 로직

각 섹터 점수 = 가중 합산 (0~100 정규화):

| 지표 | 가중치 | 설명 |
|------|--------|------|
| 뉴스 볼륨 추이 | 25% | 최근 7일 vs 직전 7일 뉴스 증가율 |
| 평균 감정 점수 | 20% | 섹터 내 종목 뉴스 평균 sentiment |
| 평균 매출성장률 | 25% | 섹터 대형주 평균 revenue_growth_yoy |
| 거시 연관성 | 20% | FRED 지표와의 섹터별 가중치 (금리↓→성장주↑ 등) |
| 모멘텀 | 10% | 최근 분기 실적 서프라이즈 비율 |

> **가정**: 거시 연관 가중치는 초기엔 하드코딩 매핑 테이블로 정의.
> 예: 금리 하락 국면 → 반도체/AI/우주 가산점, 금융 감점.

## 산출 주기

- `@Scheduled` 잡으로 **하루 1회** 배치 산출 (예: 매일 06:00 KST).
- 결과를 `Sector` 테이블의 `latest_rank`, `latest_score`, `ranked_at`에 저장.
- API는 저장된 값을 조회만 (실시간 계산 금지 → 응답 속도 확보).

## 엔드포인트

```
GET /api/v1/sectors/ranking
```

응답:
```json
{
  "success": true,
  "data": {
    "rankedAt": "2026-05-29T06:00:00Z",
    "sectors": [
      {
        "rank": 1,
        "code": "SEMICONDUCTOR",
        "name": "반도체",
        "score": 87.5,
        "highlights": {
          "newsVolumeChange": "+34%",
          "avgSentiment": 0.42,
          "avgRevenueGrowth": 0.28
        }
      }
    ]
  },
  "disclaimer": "본 정보는 투자 추천이 아닙니다.",
  "timestamp": "..."
}
```

```
GET /api/v1/sectors/{sectorId}/trend   # 섹터 트렌드 상세 (뉴스 볼륨/감정 추이)
```

## 규칙

- 점수 산출 로직은 `SectorRankingService`에 집중. 가중치는 상수/설정으로 분리해 튜닝 가능하게.
- FRED 호출 결과는 캐싱 (`caching.md`, TTL 24시간 — 거시지표는 자주 안 변함).
- 데이터 부족 섹터는 점수 산출에서 제외하고 로그 남김 (0점 처리 금지).
